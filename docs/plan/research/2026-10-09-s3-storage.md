# S3 storage for file bytes (plan and as built)

Date: 2026-10-09. Branch `s3-storage`, from v0.34.0. Operator request: "for file storage implement a s3 layer. lets use bun s3 for file". Bun 1.4.2's built-in client (`Bun.S3Client`), no S3 npm dependency.

## 1. Decisions (director)

- **Pluggable storage, local by default.** One small interface in front of every place the server reads or writes file bytes; two backends, `local` (today's layout, unchanged) and `s3`. SQLite and its WAL stay local.
- **Configuration through env**: `STORAGE_BACKEND=local|s3`, `S3_BUCKET`, `S3_ENDPOINT`, `S3_REGION`, `S3_ACCESS_KEY_ID` / `S3_SECRET_ACCESS_KEY` (and `_FILE` variants), `S3_PREFIX`. Added in this slice: `S3_ALLOW_HTTP` (see §4). Incomplete configuration refuses to start; a probe write/read/delete runs at startup.
- **Opaque keys**, no public ACLs, no presigned URLs; the server streams bytes exactly as before.
- **Streaming and limits**: no whole-file buffering, multipart for big files, every existing limit kept; the free-disk check keeps only its floor for the DB disk.
- **Consistency**: object first, then the row; orphans deleted on failure and swept hourly; Bin purge deletes objects; sweep safe on both backends.
- **Migration between backends**: a host CLI that copies, verifies by size and hash, resumes, and refuses while the heartbeat is fresh.
- **Backups**: `backup.sh` warns with S3; OPERATIONS documents bucket versioning, `aws s3 sync`, rclone. No S3 backup tool.
- **Egress**: S3 is operator-configured, server to server, not under the agent egress guard; THREAT_MODEL rows added.
- **No migration needed** (045 stays free; the Messages plan keeps its number).

## 2. Where file bytes lived (survey)

| Bytes | Before | Now |
| --- | --- | --- |
| Files documents and attachments (tasks, collections) | `DATA_DIR/documents/objects/<uuid>`, staged in `documents/.staging/<uuid>.part` | object store, namespace `documents` |
| Note pictures, whiteboard pictures | ordinary Files (same as above) | `documents` |
| Whiteboard scenes and kept versions (snapshots) | `documents/objects/<object-id>` (copy on write) | `documents` |
| Uploads in progress | `documents/.staging` | the staged writer (local: `.staging`; S3: the in-flight upload) |
| MCP and REST raw uploads (`storeRawUpload`) | same pipeline | same pipeline |
| Profile pictures | `DATA_DIR/avatars/<uuid>`, staged as `.<uuid>.part` | namespace `avatars` |
| Whiteboard thumbnails, chat tool images | SQLite blobs | unchanged (SQLite) |
| Note Markdown (current, drafts, versions) | `DATA_DIR/notes/<id>/…` | unchanged, local (see §6) |
| `push/vapid.json`, `mail-unsubscribe` key, `server.heartbeat` | `DATA_DIR` | unchanged (settings, not file bytes) |

The uploads research (docs/plan/research/2026-10-09-uploads-everywhere.md) reached the same picture: every user upload already goes through `POST /api/files` / `storeRawUpload` into one store, so later upload work uses `createDocumentWriter` and nothing else.

## 3. The interface (`server/objectStore.ts`)

```ts
type ObjectNamespace = "documents" | "avatars";
interface ObjectStore {
  backend: "local" | "s3";
  createWriter(ns, id): ObjectWriter;          // write(chunk) / commit() / discard()
  put(ns, id, bytes): Promise<void>;
  open(ns, id, expectedSize?): Promise<StoredObject>;   // size, stream(start, end), bytes(), close()
  stat(ns, id): Promise<{ id, size, modifiedMs } | null>;
  remove(ns, id): Promise<void>;               // missing = success
  list(ns): AsyncIterable<{ id | null, size, modifiedMs }>;
  sweepStaging(ns, cutoffMs): Promise<{ removed, ignored }>;
  probe(): Promise<void>;
}
```

`objectStore()` returns the configured store; `createLocalObjectStore(dataRoot)` and `createS3ObjectStore(settings)` build one directly (tests, the CLI). Errors: `ObjectIntegrityError` (`missing`, `not_regular`, `size_mismatch`; still exported as `DocumentIntegrityError`) and `StorageUnavailableError` (S3 failures, the service's error code only). `diskBytesNeeded(bytes)` is the free-disk rule. `server/documentStorage.ts` is the `documents` namespace's thin wrapper: `createDocumentWriter`, `writeObject`, `openObjectForRead`, `readObjectBytes`, `removeObject`, `objectIsIntact`, `documentObjectSizes`, `sweepDocumentFiles`.

### Call sites moved

- `server/documents.ts`: multipart and raw uploads stream into a writer (`writeFilePart`, `receiveSingleFile`, `receiveRaw`, `commitReceived`), the content route streams `opened.stream(start, end)`, the disk check uses `diskBytesNeeded`, a storage failure answers 503 `STORAGE_UNAVAILABLE`.
- `server/whiteboards/service.ts`: scene reads (`readSceneBytes`, snapshot scenes and counts), `ensureDiskSpace`.
- `server/mcpTools.ts` (`read_file`), `server/knowledge/index.ts` (file sources): `bytes()`.
- `server/avatars.ts`: store, serve, clear, and the hourly sweep go through the `avatars` namespace.
- `server/sweeper.ts`: the boot integrity check uses one listing instead of a stat per row; the orphan sweep is backend-neutral.
- `server/bin.ts`: unchanged (it already called `removeObject`).
- `server/index.ts`: the S3 probe and prefix claim at startup, and one "File storage:" log line.

## 4. Configuration (`server/config.ts`, `parseStorageConfig`)

`STORAGE_BACKEND` (`local` default), `S3_BUCKET`, `S3_ENDPOINT`, `S3_REGION` (required unless an endpoint is set), `S3_ACCESS_KEY_ID[_FILE]`, `S3_SECRET_ACCESS_KEY[_FILE]` (absolute, outside `DATA_DIR`, never both, like the vault key), `S3_PREFIX` (validated, `/` appended), `S3_ALLOW_HTTP` (new: plain http only to this machine unless set, so files and keys never cross a network in clear by accident). Missing settings are named in one startup error. Documented in `.env.example`, `compose.yaml`, OPERATIONS → Configuration, and the docs site table.

## 5. Behaviour (as built, Bun 1.4.2)

- **Startup.** `probe()` puts, gets, and deletes `<prefix>.probe/<uuid>`; any failure exits 1 with the service's error code. Then `claimS3Prefix` ties the prefix to `DATA_DIR/storage-instance` through `<prefix>.nook-instance`; another data directory's prefix refuses to start (two Nooks on one prefix would sweep each other's files).
- **Writes.** `S3Writer` uses `S3File.writer({ partSize: 5 MiB, queueSize: 2, retry: 3 })`. Bun's `write()` never applies backpressure (it buffered a 60 MiB upload whole in a test), so the writer awaits `flush()` after every 5 MiB: memory stays at about one part per upload, and every part but the last is at least 5 MiB (S3's minimum). Small files are a single PUT at `commit()` (`end()`).
- **Bun 1.4.2 cannot abort a writer**: `end(error)` still completes the upload. A discarded S3 writer therefore completes and then deletes its key. The key is a fresh UUID no row names, so nothing can read it in between, and the orphan sweep removes it if the delete fails. Invisible parts of a killed process are left to the bucket's `AbortIncompleteMultipartUpload` lifecycle rule (documented); Bun has no API to list them. `sweepStaging` is a no-op on S3.
- **Reads.** `open()` HEADs the object (size check against the row), then `stream(start, end)` is a ranged GET (`S3File.slice`). Bun 1.4.2 sends its native S3 stream chunked and drops the route's `Content-Length`, so the stream is piped through a plain `TransformStream`. Range, If-Range, HEAD, 416, ETag, CSP, and disposition are the content route's own, unchanged.
- **Consistency.** Object, then row; any failure after the object deletes it (logged, not fatal: the sweep catches a failed delete). The hourly sweep lists `documents/` and `avatars/` only, removes UUID-named objects older than an hour that no row names, and counts anything else as ignored. Bin purge removes the document's object and a whiteboard's scene and snapshot objects through the same `removeObject`.
- **Disk.** `MIN_FREE_DISK_BYTES` with S3 checks only the floor (SQLite, WAL); with local it still adds the upload's size. Agent tool images (SQLite) keep their own check.

## 6. Not moved (deliberate)

- **Note Markdown** stays in `DATA_DIR/notes`. It is the note's versioned text store (drafts, immutable versions, the current mirror) with fsync-and-rename crash recovery, read on every note open, search reconcile, and MCP read; it is small (≤ `MAX_MARKDOWN_BYTES`) and closer to the database than to file bytes. Moving it would need a second consistency design; it can be a later slice behind the same interface (a `notes` namespace) if operators ask.
- Thumbnails and chat tool images stay in SQLite (they are database rows today).

## 7. Migration CLI (`server/storage-admin.ts`)

```sh
bun server/storage-admin.ts migrate --to s3      # DATA_DIR → bucket
bun server/storage-admin.ts migrate --to local   # bucket → DATA_DIR
bun server/storage-admin.ts verify [--hash]      # the configured backend against the database
```

It copies every object the database names (live and binned documents, whiteboard scenes and snapshots, avatars), streams each through SHA-256 into the target, rejects a source whose hash differs from the row, reads the copy back and compares size and hash, and appends `namespace/id` to `DATA_DIR/storage-migrate-to-<target>.journal` (first line names the bucket and prefix; a journal for other settings is refused). A rerun skips journalled ids and replaces anything else; the journal is removed when all files are copied. It waits up to 20 s and then refuses while `server.heartbeat` is fresh (like `rotate-kek`), claims the prefix, never deletes the source, writes an audit row (`storage.migrated`, counts only), and prints next steps. Switch-over steps are in OPERATIONS → S3 storage.

## 8. Backups

`scripts/backup.sh` reads `STORAGE_BACKEND` (environment, then `.env`) and, with `s3`, prints a three-line WARNING at start and end: the archive holds the database and settings only. OPERATIONS → Backup and restore names bucket versioning (with a noncurrent expiry), `aws s3 sync`, and `rclone sync`, and says a restore needs the archive and the bucket from the same time or later.

## 9. Later options (not built)

- **Presigned downloads**: redirecting large downloads to a short-lived presigned GET would take the bytes off the server, but the browser would then fetch from the bucket's origin (a CSP and `connect-src`/`img-src` change), `Content-Disposition` and `Content-Type` would have to be forced through response-override parameters, and a leaked URL would work for its lifetime without Nook's access check. Worth it only for very large media; if done, keep it opt-in (`S3_PRESIGNED_DOWNLOADS=true`), with a lifetime of a minute and only for `attachment` downloads.
- Server-side encryption settings (SSE-KMS key id), a session token for temporary credentials, virtual-hosted-style addressing: small config additions when an operator needs them.
- Note Markdown in the store (§6).
