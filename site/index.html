Your private nook.
Notes, files, tasks, and more.

Nook is a secure, self-hosted workspace for a household or a small trusted team: Markdown notes with immutable versions, files in the same folders, task boards with subtasks and sprints, typed collections, shared calendars with reminders, a Today dashboard, a 30-day Bin, and an MCP server for trusted AI clients, all in one small Docker container.

Product

One workspace, several apps

Today opens each app after sign-in. Every app, folder, note, file, board, card, collection, and event has its own URL.

☀

Today

What needs you now: due and assigned cards, recent notes and drafts, files, rows, upcoming events, items leaving the Bin, and storage.

An Outline-like Markdown editor with slash commands, checklists, code, images, tables, and PDF export. Publish immutable versions, diff, and restore.

▤

Files

Upload, preview, download, rename, move, and share documents in list or thumbnail grid view, with per-user quotas.

▥

Task boards

⋔

Subtasks and sprints

Using Nook

Notes editor

Type / for headings, lists, checklists, quotes, code blocks, images, and tables. Drafts save automatically; Publish records an immutable version you can compare or restore.

Images

/image, paste, or drop uploads a PNG, JPEG, GIF, or WebP into the note's folder in Files and embeds it. The server's own type check must agree. Removing it from the note keeps the file.

Tables

/table inserts a 3×3 table with a header row. A floating toolbar adds or removes rows and columns; tables save as GitHub-flavoured Markdown pipe tables and scroll sideways on phones.

Download as PDF

From the editor toolbar or the phone actions menu. The browser's print dialog opens with a print layout; choose Save as PDF.

Images follow the folder's sharing. A note shared more widely than its folder shows those readers a broken image. Nothing leaks; share the folder or the image too.
Using Nook

Full-text search

The search box at the top of the note list searches the text of your notes, not just their titles.

Syntax

Every word must appear, in any order; case and accents are ignored, so creme finds “Crème”. The last word matches as a prefix while you type; end with a space for whole words. "double quotes" match an exact phrase. AND, OR, NOT, *, and title: are ordinary text. Link text, image descriptions, and code are searched; link addresses are not.

What you see

Your own notes are searched as last saved, including drafts marked Draft. Shared notes are searched as their latest published version; you never see someone else's draft. Binned notes are not searched. Title matches rank first, with a highlighted excerpt, folder, owner, and last edit.

Scope

Search covers the section you are in: All notes, Shared with me, or one folder. Search all notes widens it; opening a result from outside the section switches to All notes.

  • Ctrl+K (⌘K on a Mac) or / focuses search; Esc clears it; ↑/↓ and Enter pick a result.
  • On phones, Back from a note returns to the results with the query kept. The query lives in the tab's history state, never in the URL.
  • Up to 20 searches per 10 seconds per user (then title matches only, with a notice) and 200 characters per query. Files are not searched yet.
Using Nook

Files

Documents live in the same folders as notes. Any type is stored; only safe types are shown in the app.

Upload

Use the Upload button, drop files from your computer onto the list, or use the upload sheet on phones. Two uploads run at a time with progress, cancel, and retry. Each file may be up to MAX_UPLOAD_BYTES (100 MiB by default) and counts towards USER_STORAGE_QUOTA_BYTES (10 GiB).

List and grid

The List / Grid toggle next to sort switches between rows and responsive tiles with image thumbnails and type icons, remembered per user. Sort by name, date, or size, and filter by name.

Preview

On desktop the preview opens as a pane on the right when a file is selected; × or Esc closes it. On phones the preview is its own screen, and Back returns to the list.

Metadata is not stripped. Nook does not remove EXIF or embedded metadata (such as GPS location or author) from images or PDFs. Remove it before sharing.
Using Nook

Task boards

New board asks for a name and a template: Simple kanban, Personal to-do, Task checklist, Scrum sprint board, Epic › Story › Subtask, Bug triage, or Content pipeline. Boards start private; share one with selected accounts or everyone signed in.

Cards

New card opens a composer that sets the title, column, due date and time, assignees (up to 20), description, relations, and attachments in one step. Drag cards between columns, or use ⋯ → Move to… and Alt+arrows. Open a card over its board or as a full page.

Tags, flags, relations

Up to 10 colour tags per card from the board's tags, four flags (Urgent, Blocked, Needs review, On hold), and relations to cards on any board you can open: depends on, needed by, relates to, duplicates. A card you cannot open shows as restricted.

Columns

The owner sets each column's state (To do, In progress, Done) and an optional WIP limit; a full column refuses new cards. Done columns count as finished everywhere.

Four views

Columns, a sortable Table, a List grouped by column, assignee, tag, flag, parent, or due date, and a Calendar where you drag cards to reschedule, with an Unscheduled tray.

Filters

+ Filter adds Assignee, Tag, Flag, Due, Column, Level, Parent, Sprint, or Relations; the text box matches titles and descriptions. The view, filters, and sort live in the URL, so a filtered view is a shareable link.

Who can do what

Everyone who can open a board adds, edits, moves, and comments on cards. Only the owner changes columns, structure, sprints, and sharing. Viewers and guests only read.

Subtasks, epics, and sprints

A board starts flat. In Board settings → Structure the owner picks Task › Subtask, Sprint › Task, Sprint › Task › Subtask, Epic › Story › Subtask, or custom names for up to three levels, and which level the columns show.

Subtasks

A card lists its children as a checklist with a count such as 2/5 and a progress bar. Add subtask… adds one on Enter; ticking one moves it to the first done column. When the last is done, Nook offers to move the parent too.

Parents

A card below the top level has a parent field (Epic, Story, or Task). Drag a card onto one a level up, or use ⋯ → Set epic… on a phone. The table shows cards as a tree; the Bin keeps a tree together.

Sprints

On a sprint board, a switcher shows the active sprint, planned ones, Backlog, and All cards, with a strip of days left and done counts. The owner adds, starts, and Complete…s sprints, choosing where unfinished cards go.

My work and saved views

The top of Tasks has three segments with their own addresses: Boards, My work, and Views.

My work

Every card assigned to you on any board you can open, grouped by Overdue, Today, This week, Later, and No due date. Pick Open, To do, In progress, Done, or All; add filters; switch between a list, a table, and columns; and Save as view.

Views

A view is a saved cross-board filter and layout. Share it privately, with selected people, or with everyone; recipients read it and can Duplicate it. A view never widens access: each person sees only cards on boards they can open.

Collections

Typed tables for anything you track. Start blank or from Home inventory, Subscriptions, Expenses, Recipes, or Contacts.

Fields and rows

Up to 50 fields: text, number with a unit, date, checkbox, select, multi-select, link, note, or files. Edit cells in place on desktop, or a full-screen row on phones. Undo last change restores a row once.

Find and views

Find rows, sort by up to three fields, filter by up to ten conditions, and save the result as a view with its own URL.

Share and CSV

Share as View only or Can edit rows. Import CSV checks every row first and adds all or none; Export CSV neutralises spreadsheet formulas.

Using Nook

Calendar

Calendars with an Agenda and a Month view. Calendars creates, colours, hides, and shares them as Can view or Can edit events.

Events

Timed or all-day events in a time zone, repeating daily, weekly, monthly, or yearly, with skipped dates. Link notes, cards, and rows; people who cannot open a link see it as restricted. Cards with a due date show as Tasks due.

Reminders and push

Reminders are yours alone and appear under the bell and at /notifications. On an HTTPS origin, turn on push under Settings → Notifications; pushes carry no content.

Feed links

A subscribe link lets another calendar app read one calendar, Busy only or Full details. It is shown once, works without sign-in until you revoke it, and follows your access.

Using Nook

Bin

Deleted notes, files, cards, boards, collections, rows, calendars, and events stay in the shared Bin (the Bin button in the account row, or /bin) for exactly 30 days. Retention is fixed.

  • The Bin lists your own deleted items, newest first, with the days left; filter by kind. A card binned by someone else on your board is listed for you (the owner) and for them.
  • Everything is kept: drafts, versions, file bytes, and sharing. Nobody can read a binned item, including MCP clients.
  • A card moves to the Bin with its subtasks as one item (“+ N subitems”), and one restore brings the tree back.
  • Restore returns a note or file to its original folder (or Default if that folder is gone; the toast names the folder and any sharing that returns) and a card to the bottom of its column (or the board's first column). An item inside a binned board or collection can be restored only after its container.
  • Blank notes that were never published skip the Bin.
  • Delete forever and Empty Bin remove items permanently. An hourly sweeper, also run at boot, removes expired items.
  • Binned files still count towards the storage quota.
Using Nook

Team

Team (the Team button next to Bin, or /team) lists everyone with an account and their team role. Admins also open it from Settings → Manage team.

Roles

An Admin can do everything a member can and manages the team; a Member works as before. The first account on a new Nook is the admin; on upgrade, the oldest account becomes the admin. A Viewer reads everything shared with them or with everyone and changes nothing; a Guest reads only what is shared with them by name. Viewers and guests see a View only banner and no create, edit, share, or upload controls; viewers' MCP keys only read and guests have none. New accounts are guests unless SIGNUP_ROLE says otherwise. Nook always keeps at least one admin.

Blocking

Block signs a person out on every device and stops them signing in; MCP keys and calendar links pause, and their content stays shared. Unblock restores access with their existing password. Admins can also sign an account out everywhere without blocking it.

Privacy

Everyone sees names and roles. Only admins see emails, last seen, two-factor status, storage, and the activity log; nobody sees anyone else's private content. Admin changes ask for your password and a fresh code.

Invite links

Admins open Team → Invites and create a single-use link with a fixed role (member, viewer, or guest) that expires in 1 to 7 days, optionally bound to one email address. The link is shown once, can be revoked, and works even while registration is closed; ALLOWED_EMAILS still applies. With email set up (Resend), Nook can also send the link to the bound address.

Using Nook

Inbox

The Inbox (the button next to the bell, or /inbox) collects changes your MCP keys suggest instead of making. Nothing changes until you approve it, and only you see your keys' suggestions.

Proposals

A key with Suggest changes (inbox:write) plus a module's read permission proposes cards, card changes and comments, events, rows, and note drafts with submit_proposals. Each one shows the agent's reason as plain text, what it changes, and a before-and-after table or a line diff.

Approve or reject

Approve applies the change as you, with your access; if the item changed since the agent read it, the proposal fails and nothing is applied. Reject takes an optional reason the agent can read. Approve all works one proposal at a time.

Today and the bell

Proposals awaiting you on Today replaces Drafts from agents. The bell says which key suggested how many changes; push for proposals is off until you turn it on. Proposals expire after 14 days.

Using Nook

Routines

A routine is a prompt you keep in Nook (Inbox → Routines, /inbox/routines) for an agent to run on a schedule. Nook only says when it is due; your MCP client runs it, and everything it suggests waits in the Inbox.

Set it up

Name, instructions, the kinds of change it may suggest, optional boards, calendars, collections, or folders it is pinned to, a schedule (daily, weekdays, weekly, hourly, or manual) in your time zone, an optional bound key, and a per-run limit (25 by default). Nook enforces the kinds, pins, and limit.

Run it

A client calls list_due_routines, start_run (a two-hour lease), submit_proposals with the runId, and finish_run with a summary. In Claude Desktop each routine is also a routine.<name> prompt. A run left open is marked abandoned and the routine stays due.

Review it

Proposals are grouped by run with its summary; the bell says "Weekly review suggested 4 changes" once per run. Each routine keeps its last runs with status, proposal and tool-call counts (counted by Nook), and duration.

Using Nook

Settings → Modules

Each module has a switch, and every module is on until you turn it off. The choice is saved to your account, so it follows you to every device.

  • Notes, Files, Tasks, Collections, and Calendar: turning one off removes its tile and Today sections; its links go to Home with a Turn on in Settings hint.
  • Search, Bin, Notifications, and Team hide their boxes, buttons, and pages. Deleting still uses the Bin, reminders still arrive, and roles still apply.
  • Back steps over pages of a module that is off, and Forward stops before them until you turn it back on.
Hiding is not a security boundary. Nothing is deleted, sharing is unchanged, and MCP keys and feed links keep working. Revoke a key or link to stop it.
Using Nook

MCP server

An authenticated Model Context Protocol endpoint over Streamable HTTP lets trusted AI clients read your workspace and, with the permissions you grant, write drafts, cards, rows, and events.

1

Create a key

Open Settings → API keys, choose New key, and build its access one permission at a time (module, permission, all or chosen items) with an expiry. It is shown in full only once; Nook stores its SHA-256 hash and a short prefix, never the plaintext. Viewers can create read-only keys; guests cannot create keys.

2

Configure the client

Copy the ready-to-paste configuration. The endpoint is <your origin>/mcp and the key is sent as a bearer token:

{
  "mcpServers": {
    "nook": {
      "type": "streamable-http",
      "url": "http://localhost:2026/mcp",
      "headers": { "Authorization": "Bearer <YOUR_API_KEY>" }
    }
  }
}
3

Revoke when done

Use a separate key per client, treat keys like passwords, and revoke unused keys from the same screen.

PermissionWhat the client can do
notes:read, notes:write-draftList, read, and search published notes; create notes and folders and write drafts of your own notes. It never publishes.
notes:publishPublish a draft of your own note, only a revision the key has read. Opt-in, with a warning: shared notes become visible to their readers.
files:read, files:writeList files and folders and read text files up to 1 MiB; store text files, upload files through a one-time ticket, rename and move your own files, and create folders. Never shares or deletes, and refuses moves that would change who can see a file.
tasks:read, tasks:writeBoards, cards, comments, relations, subtasks, sprints, saved views, and cross-board query_cards; create, update, move, link, and comment on cards, plan them in sprints, manage tags and WIP limits, add and start sprints (owner only), and attach files. Never deletes.
collections:read, collections:writeQuery and read rows; add and change rows and create private collections. Never deletes or changes fields.
calendar:read, calendar:writeList calendars and events; create and change events and set your own reminders.
bin:writeMove notes, cards, events, and rows to the Bin and restore them, only together with that module's write permission. Nothing is deleted forever; at most 10 a minute and 50 a day per key, and Review → Restore all on the key undoes it.
today:readThe Today summary, limited by the key's other permissions.
team:readAdmins only: names, roles, and status of accounts.
Only what you can open. A key sees exactly what its owner may read, never anything in the Bin, and restricted items only as “restricted”. Each key is rate limited per minute and per day, and writes are recorded in the audit log with the key's id.

Quick start with Docker

You need Git, Docker Engine, and Docker Compose. Bun stays inside the image.

mkdir -p /srv/mynotes

Access

Accounts and sharing

Adding users

Add trusted addresses to ALLOWED_EMAILS, temporarily set ALLOW_REGISTRATION=true, restart, and let each person register. Disable registration afterward. New accounts get SIGNUP_ROLE (default guest; viewer or member also allowed) until an admin changes their role in Team.

Admins and recovery

Admins manage roles and blocks in the Team app. If the only admin is locked out, run docker compose exec mynotes bun server/team-admin.ts set-role user@example.com admin (or unblock, or list) on the host.

Permission precedence

Notes and files are private by default. Folder access applies to inherited items, but an item's own sharing always wins. Nothing becomes public.

Authentication

Two-factor authentication

Users enroll under Settings → Security. The grouped setup key is entered once in an authenticator app. Sign-in uses the current six-digit code or one complete recovery code.

Recovery codes are encrypted. Viewing or replacing them requires a password and fresh TOTP code. Each works once.

Administrator reset

docker compose exec app bun server/reset-totp.ts user@example.com

This revokes the user’s sessions and requires fresh enrollment.

Data

Storage and migrations

On-disk layout

/data/
├── mynotes.sqlite (+ -wal, -shm)
├── notes/<note-id>/
│   ├── current.md
│   ├── draft.md
│   └── versions/000001.md
├── documents/
│   ├── objects/<document-id>
│   └── .staging/<document-id>.part
└── backup/

File names live only in SQLite; bytes are stored under server-generated ids. Uploads stream to .staging on the data volume, and a sweeper removes abandoned staging files at boot and hourly. The data directory is mode 0700; database and Markdown files are 0600; symlinks are refused.

Automatic migrations

Numbered migrations run transactionally before traffic is accepted and are recorded in schema_migrations. Released migrations are append-only.

One instance per data directory. Upload slots, locks, rate limits, and the sweeper live in the process. Never point a second container or a dev server at the same directory.
Operations

Backup and restore

The backup script briefly stops the app for a consistent snapshot of SQLite, notes, and files, verifies gzip, and keeps five archives. A second run within seven days is skipped unless forced.

./scripts/backup.sh
./scripts/backup.sh --force

Weekly cron (Sunday 03:00)

0 3 * * 0 cd /path/to/nook && ./scripts/backup.sh >> /srv/mynotes/backup/backup.log 2>&1

Restore into an empty directory

mkdir -p /srv/mynotes-restored
tar -xzf /srv/mynotes/backup/mynotes-*.tar.gz -C /srv/mynotes-restored
MYNOTES_DATA_DIR=/srv/mynotes-restored docker compose up -d --build
  • Archives include documents/objects but not documents/.staging.
  • Archive size and the time the app is stopped grow with stored files; gzip gains little on media, and five archives multiply the disk use.
  • Binned items are backed up like live ones. Anything deleted forever can survive in older archives for about five weeks.
  • Start only one Nook instance on a restored directory, with the same .env.
Store .env separately. Backups intentionally exclude it and its TOTP key.
Networking

Network and HTTPS

Compose publishes port 2026 for LAN access. Prefer Tailscale Serve or a TLS reverse proxy for HTTPS.

APP_ORIGINS=http://localhost:2026,http://192.168.10.20:2026,https://your-device.your-tailnet.ts.net
  • Use HTTPS for non-local access.
  • Set APP_ORIGINS to a comma-separated list of exact trusted origins; never a wildcard.
  • Keep COOKIE_SECURE=true with HTTPS.
  • Plain HTTP requires COOKIE_SECURE=false and is less safe.
  • Never serve the data directory as static content.
Security

Security model

Application

Argon2id passwords, opaque HttpOnly sessions, SameSite cookies, CSRF tokens, CSP, and authorised reads for every note, file, search result, and MCP call.

Data

AES-256-GCM TOTP data, hashed API keys, restrictive permissions, symlink refusal, atomic writes, and mutation locks.

Container

Non-root UID, read-only root, dropped capabilities, no-new-privileges, and a small tmpfs.

Supported shape: a single Docker Compose host using local SQLite/WAL storage. Rate limiting is in memory and does not coordinate across replicas.

Help

Troubleshooting

Container cannot write data

Ensure the host path exists and is writable by UID/GID 1000.

Login fails behind a proxy, Tailscale, or LAN address

Add the exact scheme, host, and port to APP_ORIGINS. Plain HTTP also needs COOKIE_SECURE=false; prefer HTTPS.

TOTP code is rejected

Synchronize phone and server clocks. Codes are one-time; use a fresh code or recovery code.

An upload is refused

The message names the limit: file size (MAX_UPLOAD_BYTES), your quota (USER_STORAGE_QUOTA_BYTES, which includes the Bin), or free disk space (MIN_FREE_DISK_BYTES).
